# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

Zettelfrieden ("Versicherungsmanager") is a self-hosted insurance policy management platform with OCR-driven document analysis. German-language product; UI strings and domain terms (Beitragsanpassung, Kündigungsfrist, SF-Klasse, etc.) are in German — keep new user-facing strings and comments consistent with that. It is a two-service app: a Next.js frontend and a FastAPI backend, meant to run via Docker Compose.

## Commands

### Frontend (`frontend/`)
- `npm run dev` — starts Next.js dev server on `0.0.0.0` (Turbopack)
- `npm run build` — production build
- `npm run start` — run production build
- `npm run lint` — ESLint (flat config, `eslint.config.mjs`)
- No test runner is configured in this repo.

### Backend (`backend/`)
- No lockfile/venv tooling beyond `requirements.txt`; install with `pip install -r requirements.txt`.
- Run locally: `uvicorn main:app --host 0.0.0.0 --port 8000` (from `backend/`).
- Tests: `pip install -r requirements-dev.txt`, then `pytest` from `backend/` (security regression suite in `tests/`, runs against a throw-away SQLite DB in a temp dir; CI runs it too). No linter or formatter is configured.

### Full stack
- `docker-compose up --build` from the repo root builds and runs both `backend` and `frontend` containers (`network_mode: host`, backend on `:8000`, frontend on `:3000`).
- `install.sh` / `proxmox-install.sh` / `update.sh` are end-user deployment scripts for Proxmox LXC / Linux hosts, not development tooling.

The backend has a security-focused pytest suite (`backend/tests/`); the frontend has no test runner — verify frontend changes by running the app (see the `run` skill) and exercising the affected flow manually.

## Architecture

### Request flow: frontend never talks to the backend directly
The Next.js app calls its own `/api/*` routes; `frontend/src/app/api/[...path]/route.ts` is a catch-all proxy that forwards every method to the FastAPI backend. It tries a list of candidate `BACKEND_URLS` (env `BACKEND_URL`, then Docker/host fallbacks) with a retry loop, since the backend container may still be booting. `frontend/src/lib/api.ts` is the single client-side wrapper (`api.get/post/put/postForm/delete`) — it attaches the JWT bearer token from `localStorage` and redirects to `/session-expired` on 401. Always route new frontend API calls through `lib/api.ts`, not raw `fetch`.

### Backend module layout (`backend/`)
- `main.py` — FastAPI app setup, CORS, router registration, and startup hooks. On startup it: creates tables, runs `auto_migrate_sqlite()` (hand-rolled `ALTER TABLE ... ADD COLUMN` / `CREATE INDEX IF NOT EXISTS` checks — **there is no Alembic migration flow**; new SQLAlchemy model columns or indexes must also be added here as a migration step, and existing installs keep any columns removed from `models.py` as harmless orphans rather than risking a `DROP COLUMN` migration), seeds a default `admin`/`admin` user if none exists, and starts the backup-scheduler daemon thread plus a daily vendor-pattern sync.
- `database.py` — SQLAlchemy engine/session/`Base`, SQLite by default (`DATABASE_URL` env var); `resolve_sqlite_path()` is the single source of truth for turning that URL into a filesystem path (used by both `database.py` and `main.py`'s migration code — don't reintroduce a second copy).
- `models.py` — SQLAlchemy models: `User`, `Insurance`, `PremiumHistory`, `Claim`, `Document`, `Category`, `SystemSetting`. `Document` doubles as both an insurance attachment and an "Inbox" item (`is_inbox`, `status`, `ai_data` JSON string) before it's assigned to an `Insurance`. Foreign-key columns (`owner_id`, `insurance_id`) are indexed.
- `schemas.py` — Pydantic request/response models.
- `auth.py` — JWT (PyJWT, `HS256`, 7-day expiry) + bcrypt password hashing. `get_current_user`/`get_current_active_user` are the standard FastAPI dependencies for protected routes; `SECRET_KEY` comes from env (defaults to `changeme123` — must be overridden in real deployments). Every endpoint that serves a stored file or user-owned resource must depend on `get_current_active_user` and check ownership — `routers/documents.py`'s `view_document`/`download_document` previously skipped this and leaked any document to unauthenticated requests; treat that pattern as a regression class to watch for in new endpoints.
- Security building blocks (each has a docstring explaining the threat it addresses): `request_limits.py` (ASGI body-size middleware, mirrored by the Next proxy in `frontend/src/app/api/[...path]/route.ts` — keep both in sync), `upload_validation.py` + `safe_archive.py` (upload/ZIP-import limits, name sanitizing), `pattern_safety.py` + `pattern_runner.py` (learned regex patterns are untrusted: static checks, then run in a killable subprocess), `totp.py` (2FA + recovery codes, login flow in `routers/users.py`), `audit.py` (`AuditLog` table; call `audit.log_event` for any new security-relevant action, never put secrets in `detail`), `secrets_crypto.py` (settings encrypted with a key derived from `SECRET_KEY`), `user_data.py` (complete account erasure incl. files), `http_utils.py` (Content-Disposition/ICS escaping), `oidc.py` + `oidc_settings.py` + `routers/oidc.py` (single sign-on with OpenID Connect/PKCE: the provider is trusted only after issuer/audience/signature/nonce checks, users are matched by `(oidc_issuer, oidc_sub)` and linked by email only when the provider marks it verified, the session reaches the browser through the proxy's `X-Refreshed-Token` handling and the `zf_oidc` flow cookie travels as `X-OIDC-Flow`; tests use a fake provider in `tests/oidc_fake.py`). Secrets (SMTP/backup passwords) are never returned by GET endpoints — only `*_set` flags.
- `routers/` — FastAPI routers, each `include_router`-mounted in `main.py`: `users` (auth/admin/profile/SMTP config/password-reset-by-email/calendar-webcal), `insurances` (CRUD + premium history + claims), `documents` (upload/OCR pipeline), `inbox` (Posteingang workflow), `backup` (DB+documents backup/restore, encrypted archives). SMTP-based e-mail (password reset, test mail, daily cancellation-deadline reminders) is a real, supported feature — configured per-instance via `SystemSetting` rows (`smtp_server`, `smtp_port`, etc.) through the admin "E-Mail & SMTP Server" settings card, not env vars. There is **no** Netzlaufwerk (WebDAV) feature in this codebase (removed on purpose) — don't reintroduce `netdrive-*` endpoints/columns or a WebDAV server without being asked.
- `ocr.py` — Document understanding pipeline, **rule-based, no language model**: text comes from `pdftotext -layout` (pypdf fallback) for PDFs with a text layer and from Tesseract (`deu`, pages rendered at 3300 px, straightened by `image_prep.py`) for scans; `extract_insurance_data()` runs the hand-written German regex/keyword extractor `extract_insurance_data_regex`, then learned vendor patterns, then `finalize_extraction`, naming and `assess_fields`. A language model (Qwen2.5-1.5B via llama-cpp-python) was part of the app and was removed on purpose: measured against the rules it gained almost nothing (rules 14/14 on the real documents; as a gap filler it added 2 insurers in 16 invented letters and 4 of 6 numbers in awkward layouts, one of them wrong) while costing 1.5 GB RAM, 1.1 GB disk, a compiler in the Docker build and a pinned model download. Do not bring it back without new measurements. Dedicated fallback extractors (policy number, cost, dates, Regionalklasse) are part of the rules. The frontend's `/documents/extract` preview call and the follow-up `POST /documents` save call share one analysis: `create_document` accepts an optional `extracted_data` form field so the frontend can pass along the already-extracted result and skip the second pass - keep that field wired up when touching the upload flow. `json.dumps(...)` calls that serialize an `extract_insurance_data()` result must pass `default=str`, since the dict contains real `datetime.date` objects that aren't natively JSON-serializable.
- `document_naming.py` — the suggested document name (`suggested_title`/`document_title`/`subject`, set centrally at the end of `extract_insurance_data`): insurer + kind of letter + date, recognised from the heading area only, never the policy number and never a sentence from running text. `backend/tools/eval_extraction.py` measures extraction on real documents kept outside git in `backend/eval/` (personal data, in `.git/info/exclude` and `backend/.dockerignore` - never commit or bake into an image). `expected.json` there holds what the pages really say (checked by looking at them, not copied from the extractor); computed values (cancellation date, end date the letter does not state) count as "not read". Run it after every change to `ocr.py`.
- `document_types.py` + `ocr.finalize_extraction()` — last step of every extraction of every extraction: the kind of letter (`document_naming.detect_kind`) decides `doc_type`, which is always an entry of the document-type list in `UploadModal.tsx` (the insurance kind, e.g. "Kfz-Versicherung", is `insurance_type`). Informational types (`is_informational`: Sonstiges, Verbraucherinformationen, Kundeninformationen, Produktinformation, Beratungsprotokoll) deliver no contract fields; `documents.py`/`inbox.py` also refuse to touch cost, premium history or insurance data for them, the type the user chose wins over the recognised one. Credits and refunds are never the premium (`extract_cost_fallback`, `refund_amount` separate); a terminated contract has no cost. Measure changes with `tools/eval_extraction.py`.
- `image_prep.py` — straightens page images before Tesseract (`ocr.read_page_image`, Pillow only: tilt found by projection profile on a small copy, EXIF orientation, contrast); falls back to the raw image on any error. A page that was scanned turned reads as nonsense and Tesseract's mean word confidence drops from ~90 to 23-35: only then (`ocr.read_page_image`, confidence from the same TSV run as the text) the other three orientations are tried and a clearly better reading wins. Tesseract's own orientation detection (OSD) was measured and rejected: it takes upright pages for upside down. `tools/eval_ocr.py` compares OCR settings by numbers (real scans via vocabulary share, tilted/noisy copies of a text-layer PDF via word F1); measured and rejected: other `--psm` modes, `deu+eng`, binarising. Pages are rendered at 3300 px (`OCR_MAX_PAGE_SIDE_PX`, ~280 dpi): at 2400 a policy number on the green card and a class digit were lost; the choice is made with `tools/eval_extraction.py --side N` on the real documents, not with the word statistics of `eval_ocr.py`.
- `field_checks.py` — every extracted value is checked against the document text (`assess_fields`, result in `field_checks`): `gefunden` (with page and line, page from the `--- Page n ---` markers that both the PDF text layer and OCR output carry), `berechnet` (the cancellation date is always end of term minus one month, an end date may be start plus a year), `unsicher` (not in the text, or an amount only guessed as the first plausible one: `cost_certain`). Classes and numbers are matched OCR-tolerantly (RO5 = R05) but never inside longer words or numbers. The frontend shows the result with `components/FieldChecks.tsx` (panel in the upload dialog and the inbox assign dialog, `CheckHint` under a form field while it still holds the extracted value); it uses the `--calm-*` tokens.
- `document_hash.py` — duplicate detection: every stored `Document` carries `file_hash` (SHA-256 of the file; set on upload, inbox upload and user import, existing rows are filled by a background thread at startup). `/documents/extract` returns `duplicate` (an earlier document of the same user with the same file) and the inbox list returns `duplicate_of` for the later of two copies; the UI only warns (`components/DuplicateNotice.tsx`), saving stays possible. Lookups are always limited to the current user's own documents (owner or owner of the insurance) so a hash never reveals another user's file.
- `page_select.py` + `ocr.read_text_layer/ocr_pdf_pages` — which pages of a PDF are read. A text layer is read completely with Poppler's `pdftotext -layout` (pypdf as fallback; tables keep their shape) and the pages with the most contract data are kept (first 3 always, 8 in total); a scanned PDF is recognised in batches (5, then 3 more ...) and stops once a premium is found, the letter is an information leaflet, or 15 pages are reached. Layout text has wide column gaps: `llm_text` squeezes them before cutting long lines.
- `tools/synthetic_letters.py` — 22 invented letters of other insurers and layouts (6 deliberately awkward), used by `tests/test_policy_numbers.py`. `ocr.number_after_label` reads a policy number behind a label in any layout ("WG 5544-3321", "Police: 12-3456789-0", label and number on separate lines); on these letters the number was found in 6 of 16 before and in 16 of 16 after, but the rules were tuned on them: the awkward six (0 of 6) are the honest test.
- `learning.py` — "Vendor pattern" learning loop: after a document is verified, `learn_from_feedback()` derives anonymized regex anchor patterns per insurer and merges them into an XOR/base64-"encrypted" (`vendor_patterns.enc`, not real cryptography) pattern store, which is later reused in `ocr.py` to bias future extraction for the same company. `sync_patterns_with_github()` does a scheduled bidirectional pull/merge/push of this file with the project's public GitHub repo — **treat this file with care: it will auto-commit and `git push origin main` from a running backend instance.** This only runs from the OCR extraction path itself (document create/reanalyze/inbox-analyze); don't re-add a secondary trigger on generic insurance-metadata updates, since that previously re-ran the encrypt/write cycle on every unrelated field edit for no benefit.
- `sanitizer.py` — Regex-based PII stripper (`sanitize_text_for_learning`) that must scrub names/addresses/IBANs/policy numbers/phone numbers/plates before any OCR text is persisted into the learned pattern store. Any change to `learning.py` that stores raw document text must go through this sanitizer first — zero-PII-leak is a hard product requirement, not a nice-to-have.
- `backup_scheduler.py` — Background thread wrapping the backup logic in `routers/backup.py` (retention by days/count, encrypted zip archives of DB + documents), plus a once-per-24h check that e-mails users an upcoming-cancellation-deadline reminder (`check_and_send_cancellation_notifications`, only sends if an admin has configured an SMTP server and the user opted in via `email_notifications_enabled`). The WebCal/iCal export in `routers/users.py` (14-/7-day calendar alarms) is a separate, SMTP-independent reminder path that always works.

### Frontend layout (`frontend/src/`)
- `app/` — Next.js App Router pages: `page.tsx` (dashboard/list), `insurance/[id]/page.tsx` (detail view with tabs: Stammdaten, Beitragsentwicklung, Dokumente, Schadensfälle, Notizen), `inbox/`, `login/`, `register/`, `admin-setup/`, `forgot-password/`, `reset-password/`, `session-expired/`, `settings/`.
- `components/` — feature components (`InsuranceDetail`, `UploadModal`, `CancellationModal`, `TaxExportModal`, `Navbar`, `ThemeProvider`, `CompanyLogo`, `Footer`) plus `components/ui/` shadcn primitives (base-nova style, see `components.json`; path aliases `@/components`, `@/lib`, `@/components/ui`).
- The session token lives in an httpOnly cookie (`zf_session`) set by the Next proxy; scripts never see it. `lib/session.ts` only keeps a harmless "was signed in" hint and clears cached personal data on sign-out.
- Visual styles are `data-style` values on `<html>` (see `ThemeProvider.tsx` and the style blocks in `globals.css`): `dark-calm` (default), `dark-glass` (old neon look) and `apple-light`. `dark-calm` re-colours the whole app by redefining Tailwind's `--color-*` variables (zinc scale, plus green/yellow/red as the only meaningful colours), so prefer the semantic tokens (`--calm-signal` = deadline, `--calm-good`, `--calm-bad`, `--tone-1..6`) over new hard-coded colours, and define any new token for `apple-light` too. Display headings use `font-display` (Fraunces), body text Instrument Sans (self-hosted via `@fontsource-variable`). No emojis in the UI: use `lucide-react` icons. Motion uses GSAP sparingly (`lib/motion.ts`: one intro on the dashboard, reactions to user actions) and must respect `prefers-reduced-motion`.

### Important cross-cutting behaviors to preserve
- **Non-destructive document uploads**: uploading a new document for an existing `Insurance` must never overwrite its display name, and must never touch `is_suspended`/`suspension_reason` — these are described in the README as guarantees ("Namensschutz & Ruhendstellungs-Garantie") and are checked for in `routers/documents.py` / `routers/insurances.py`.
- **Licence headers:** every source file starts with `Copyright (c) 2026 Dennis Guse`, `SPDX-License-Identifier: MIT` and a pointer to `LICENSE` (no "All rights reserved": it contradicts the MIT grant). The files in `frontend/src/components/ui/` come from shadcn/ui and carry its notice instead. `backend/tests/test_license_headers.py` fails for any new file without the header. Third-party licences, fonts and the GSAP/Poppler/libvips notes live in `THIRD_PARTY_NOTICES.md`: when adding a dependency, add it there (check its licence first, copyleft needs a conversation).
- **Name:** the product is called Zettelfrieden (it was Noxus Policy; the GitHub repository is `KaelanTesseract/Zettelfrieden`, the old address only redirects). Nothing a user sees carries the old name. A few technical strings keep it on purpose because changing them would make existing data unreadable: the backup header `NOXUSBK1` (`routers/backup.py`), the strings the encryption keys are derived from (`secrets_crypto.py`, `learning.APP_CIPHER_KEY`, the backup fingerprint - old backups, stored SMTP passwords and the pattern store would become unreadable), the legacy backup extension `.noxusbackup` (still listed, restorable and rotated next to the new `.zfbackup`; user exports are `.zfuser`, the old `.noxususer` is still accepted on import) and the banned-password entries. The cookies are `zf_session`/`zf_oidc` and the hint `zf_signed_in` (renaming them signed everyone out once). Do not reintroduce a repository-name resolver in the scripts or `learning.py`: there is one `REPO_URL`/`GITHUB_REPO`.
- Certain `doc_type`s (Sonstiges, Verbraucherinformationen, Kundeninformationen) are archived as documents only and must not update `Insurance` contract fields.
- **Which letter may change the term of an existing contract** (`document_types.may_set_start/may_set_end`, mirrored in `UploadModal.tsx`): only a policy sets beginning and end, a supplement ("Nachtrag") only the end (its "Beginn der Änderung" is not the contract start), invoices, price adjustments and the rest leave beginning, end and notice date alone. The notice date is `ocr.one_month_before(end)` (same day of the previous month, clamped to its last day: 31.12. -> 30.11.), and a letter about an ended contract has none.
- This version of Next.js/React (Next 16, React 19) may include breaking API/convention changes relative to older training data — the frontend's own `AGENTS.md`/`CLAUDE.md` (`frontend/AGENTS.md`) instructs checking `node_modules/next/dist/docs/` before writing Next.js code; follow that when touching `frontend/`.
